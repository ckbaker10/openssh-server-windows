# Build on Linux

The build produces Windows x86_64 programs for Cygwin. It requires neither
Windows as a build system nor the Microsoft SDK or Windows OpenSSH components.

## Requirements

- Linux x86_64 with working rootless Podman.
- Git, Python 3.11 or later, and network access for container and package downloads.
- ShellCheck and Hadolint for validation.
- GnuPG when deliberately updating the package lock file.

Run all containers as a regular user. Image names are fully qualified;
images prefixed with `localhost/` are built by this project.

## Clone and build

```sh
git clone https://github.com/ckbaker10/openssh-server-windows.git
cd openssh-server-windows
bash scripts/build.sh
```

Adjust parallelism if needed:

```sh
BUILD_JOBS=8 bash scripts/build.sh
```

The script downloads the archives pinned in `build/inputs.lock.json` and checks
their sizes and hashes. It then builds `build/Containerfile`, prepares the
Cygwin sysroot, applies the cross-build patch, compiles OpenSSH and runs
`scripts/package.py`. The compiler targets `x86_64-pc-cygwin`; OpenSSL and zlib
come from the verified Cygwin packages. Kerberos, PAM, libedit and built-in
FIDO device access are disabled.

## Output

| File | Contents |
| --- | --- |
| `dist/openssh-10.6p1-cygwin-x86_64.zip` | Server, clients, runtime, helpers and guides |
| `dist/openssh-10.6p1-cygwin-x86_64-sources.tar` | Corresponding sources, signed package index and patches |
| `dist/SHA256SUMS` | SHA-256 hashes of both archives |

The ZIP contains a build manifest with file hashes, DLL imports, package and
tool versions, plus `inputs.lock.json` and a separate payload SHA256SUMS with
a PowerShell verifier. The manifest covers every file except itself.
The payload checksum list excludes itself and the manifest. Man and Info pages
are removed; Windows paths and name collisions are checked.

`work/` contains downloads, the sysroot and generated build data. Like `dist/`,
it is not committed. Rebuilding replaces the build directories generated by
the project. The base image and cross-toolchain are pinned; the resolved RPM
versions and image ID are recorded in the manifest. Different toolchain images
are not guaranteed to produce identical bytes.

## Check the package and helpers

Run the ZIP check before tests that use the extracted package:

```sh
podman run --rm --name openssh-server-windows-check \
  -v "$PWD:/project:Z" localhost/openssh-server-windows-builder:10.6p1 \
  python3 scripts/check-package.py
python3 -m unittest discover -s tests -v
shellcheck -S warning scripts/*.sh packaging/*.sh
hadolint build/Containerfile build/Containerfile.wine
```

Check PowerShell syntax, the package verifier and the user helper on Linux:

```sh
podman run --rm --name openssh-server-windows-powershell-check \
  -v "$PWD:/project:Z" mcr.microsoft.com/powershell:lts-ubuntu-22.04 \
  pwsh -NoProfile -File /project/tests/check-powershell.ps1
podman run --rm --name openssh-server-windows-user-check \
  -v "$PWD:/project:Z" mcr.microsoft.com/powershell:lts-ubuntu-22.04 \
  pwsh -NoProfile -File /project/tests/check-user-setup.ps1
```

User helper tests replace Windows accounts, NTFS, service control and backup
mode operations with controlled test functions. They check behavior and error
handling, but do not replace execution on Windows PowerShell 5.1.

## Supplemental runtime test

```sh
podman build -f build/Containerfile.wine \
  -t localhost/openssh-server-windows-wine:10.6p1 .
podman run --rm --name openssh-server-windows-wine-smoke \
  -v "$PWD:/project:Z" localhost/openssh-server-windows-wine:10.6p1 \
  bash scripts/smoke-wine.sh
```

Wine checks versions, Bash, key generation and `sshd -t`, including an explicit
Cygwin PATH with a reduced initial PATH. Use a new test key for each candidate.
Wine is a supplemental check; validate service operation, user switching, NTFS,
reboots and real logins separately on Windows. Releases remain prereleases
until that validation is complete.

## Update the inputs

```sh
python3 scripts/inputs.py refresh-lock
```

This verifies the pinned official Cygwin signing key and updates the selected
package set. It does not automatically select a new OpenSSH version: version
values and source package selection are currently fixed in the build, packaging
and validation scripts. For a version change, update the lock file, source
paths, scripts, tests, image tags and documentation together. Rebuild and check
everything after changes. Provide the sources for the shipped components
alongside the ZIP and SHA256SUMS.
